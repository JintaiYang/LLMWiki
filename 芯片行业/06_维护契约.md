# 维护契约 — 芯片行业 LLM Wiki

## 1. 架构

```text
芯片行业/
├── 01_收件箱/       待处理资料
├── 02_原始资料/     原始证据与来源卡片
├── 03_模板/         页面模板
├── 04_运维报告/     结构健康检查
├── 05_知识库/       行业地图、公司、产品、机会等业务知识
├── 06_维护契约.md   本文件
├── 07_导航首页.md   人类研究入口
├── 08_索引.md       全局页面索引
└── 09_操作日志.md   只追加的维护记录
```

`05_知识库` 当前保留实际使用的芯片研究模块；新增模块必须有明确研究职责和入口页，不能仅创建空目录。

## 2. 必需 Frontmatter

每篇 Markdown 必须包含：

| 字段 | 规范 |
|---|---|
| `source_url` | URL 数组；无来源时写“待验证” |
| `evidence_level` | A/B/C/D/待验证 |
| `updated_date` | YYYY-MM-DD |
| `related_links` | 至少一个有效 Obsidian 双链 |
| `key_insight` | 一句话研究结论或页面用途 |
| `next_action` | 下一步可执行动作 |

## 3. 证据等级

| 等级 | 来源与使用方式 |
|---|---|
| A | 监管披露、财报、招股书、公司公告、政府文件，可作为事实基线 |
| B | 公司官网、产品手册、投资者交流、行业协会，可作为准一手事实 |
| C | 主流媒体、券商研报、专家访谈，用于交叉验证和形成研究线索 |
| D | 社区、自媒体、未经核实转述，只能作为待验证线索 |
| 待验证 | 无来源、口径冲突或尚未完成核验 |

不得因观点符合预期而提高证据等级。预测、推断和投资判断必须与事实分开。

## 4. 页面结构

研究页面优先包含：

1. 一句话判断
2. 已确认事实及来源
3. 研究推断及依据
4. 投资判断、成立条件和证伪条件
5. 待验证事项
6. 关联网络
7. 下一步行动

索引、模板和治理页面可按职责调整正文结构，但仍必须满足 Frontmatter 和双链要求。

## 5. 摄入工作流

1. 新资料进入 [[收件箱说明]]。
2. 记录发布机构、日期、URL 和资料类型。
3. 分配证据等级并创建来源卡，归入 [[原始资料库索引]]。
4. 抽取可复用事实，回写公司、产品、地图、概念或机会页。
5. 无法核实的信息写入 [[芯片行业 validation log]]。
6. 更新 [[08_索引]] 和 [[09_操作日志]]。

## 6. 查询工作流

1. 从 [[07_导航首页]] 或 [[08_索引]] 定位页面。
2. 同时阅读相关原子笔记和来源页面。
3. 回答时区分事实、推断和待验证内容。
4. 可复用的新结论应回写知识库，而不是只保留在对话中。

## 7. 持续跟踪

- 周期、价格、库存、产能、利用率和 Capex 由 [[芯片行业 tracker]] 维护。
- 机会成立条件与风险证伪条件分别维护在 [[机会库索引]] 和 [[芯片行业 risk map]]。
- 周度复盘归档到 [[周报归档索引]]。

## 8. 健康检查

每次结构性变更后检查：

- 六字段是否完整；
- 证据等级和日期格式是否合法；
- 双链是否可解析；
- 是否存在孤立页或重复文件名；
- [[07_导航首页]] 与 [[08_索引]] 是否覆盖现有模块；
- 空目录是否有明确用途和入口；
- 不确定事实是否进入验证日志。

结果写入 `04_运维报告`，并在 [[09_操作日志]] 追加记录。
