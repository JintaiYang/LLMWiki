# 低空经济系统架构

## 一句话判断
低空经济不是“飞行器 + 一个 App”，而是由政策治理层、空域与网络层、航空器层、基础设施层、运营服务层和数据闭环层共同组成的复杂系统；任何一层掉链子，商业化都会减速。

## 核心事实
| 架构层 | 主要内容 | 关键问题 |
| --- | --- | --- |
| 治理与规则层 | 政策、条例、监管、标准、试点 | 什么能飞、谁来管、责任如何分配 |
| 空域与网络层 | 空域划设、协同管理、通信、导航、监视、Remote ID、UTM | 飞行活动能否被看见、管住、调度 |
| 航空器层 | eVTOL、工业级无人机、飞控、航电、动力、电池 | 性能、安全、冗余、适航 |
| 基础设施层 | 起降场、充换电、维修、气象、消防、调度平台 | 起得来、落得下、补得上、修得好 |
| 运营服务层 | 运营主体、培训、维修、保险、任务组织 | 谁有资格、谁能稳定运营 |
| 数据闭环层 | 飞行数据、利用率、故障率、订单、回款 | 是否能从试点进入商业优化 |

## 运行逻辑
1. [[中国低空经济政策体系]] 与 [[民用无人驾驶航空器监管]] 给出规则边界。
2. [[空域分类与协同管理]] 与 [[低空智联网与通信导航]] 提供飞行活动的可管理性。
3. [[eVTOL技术路线]]、[[工业级无人机技术体系]] 和各核心子系统决定产品能力。
4. [[起降场与低空基础设施]] 决定场景是否具备持续运行条件。
5. 运营主体在取得必要资质后，才能把订单转成飞行小时、收入和回款。

## 投资含义
- 真正能穿越周期的公司，往往不只卡某个单点技术，而是卡在系统中的关键接口位置。
- 对基础设施和平台类公司，重点看“是否接入真实运行体系”，而不是仅有规划或演示中心。
- 对整机公司，系统架构视角有助于识别“证照已前进，但运营配套仍滞后”的错配。

## 关键指标
- 治理层：政策、标准、地方试点与预算节奏。
- 运行层：TC/PC/AC/OC 与飞行小时，见 [[适航进度跟踪器]]。
- 项目层：起降场、平台和网络项目的招标、验收和运维，见 [[订单与项目跟踪器]]。
- 经营层：收入、回款、利用率和维护效率，见 [[核心指标跟踪器]]。
