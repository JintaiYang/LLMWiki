# 银行研究标的对比仪表盘设计

> 日期：2026-08-11
> Vault：`/Users/yangjintai/Documents/LLM wiki/银行`
> 定位：本地静态网页，用于横向对比18家重点覆盖银行的核心指标，并快速跳转到知识库对应概念/命题页面
> 状态：设计已确认，进入实现

## 1. 背景与目标

知识库（`05_知识库/03_银行库/`）已对18家重点银行建立了基础档案（`bank_profile`）、深度研究（`deep_research`）和核心命题（`investment_thesis`）页面，但缺少一个能"横向对比多个标的核心指标"的入口——目前只能逐个打开 Markdown 文件比较。

本仪表盘的目标：

- 把18家重点银行的核心指标汇总到一张可排序、可筛选的表格里；
- 提供卡片视图作为表格的补充展示形式；
- 点击银行名可在网页内预览知识库原文摘要，也可一键跳转 Obsidian 打开完整页面；
- 纯本地使用，零安装依赖，运行 `python3 scripts/generate_dashboard_data.py` 刷新数据后，用浏览器打开 `dashboard/index.html`（或起个本地静态服务）即可查看。

## 2. 不在本次范围内

- 不做数据库、不做后端服务、不做自动 watch 文件变化并热刷新；
- 不覆盖全部约60家银行，仅覆盖18家已建立 `<银行名> 深度研究.md` 的重点银行；
- 不做部署、不做多用户协作；
- 不修改现有知识库 Markdown 文件的内容结构。

## 3. 数据来源与提取规则

### 3.1 银行范围判定

以 `05_知识库/03_银行库/` 目录下存在 `<银行名> 深度研究.md` 文件作为"纳入仪表盘"的判定依据。

### 3.2 每家银行的数据来源（三个文件）

| 来源文件 | 提取内容 |
| --- | --- |
| `05_知识库/03_银行库/<银行名>.md`（`bank_profile`） | frontmatter（银行类型、tags、updated）+ "2.3 核心财务摘要"表格中的：总资产、ROE、NIM、营收增速、归母净利润增速、不良率、拨备覆盖率、拨贷比、CET1、PB、PE、股息率 |
| `05_知识库/17_投资命题/<银行名> 核心命题.md`（`investment_thesis`） | 正文中 `**命题状态**：xxx` 一行，解析出命题状态 |
| `05_知识库/03_银行库/<银行名> 深度研究.md`（`deep_research`） | 仅用于确认该行是否属于"重点覆盖"，以及提供跳转链接 |

### 3.3 解析规则

- 使用正则表达式匹配 Markdown 表格行 `| 指标名 | 数值 | ... |`，按指标名关键字（如"ROE"、"NIM"、"不良率"、"拨备覆盖率"、"拨贷比"、"核心一级"/"CET1"、"PB"、"PE"、"股息率"）做模糊匹配提取数值列；
- 数值列中如果是"待验证"、"NA"、空、或无法匹配到关键字，一律记为 `null`；
- 命题状态从"**命题状态**："后面的文本提取，做归一化映射：
  - 包含"证伪"/"失效" → `falsified`
  - 包含"证实" → `confirmed`
  - 包含"加强" → `strengthened`
  - 包含"削弱" → `weakened`
  - 包含"开放" → `open`
  - 其他/未找到 → `unknown`
- 任何单个文件缺失、字段缺失都不能导致整个脚本报错退出；用 `try/except` 包裹单个银行的解析，出错时记录 warning 并该银行数据尽量保留已提取到的字段。

## 4. 前端设计

### 4.1 技术栈

纯静态 HTML + CSS + 原生 JavaScript（ES6+），不引入构建工具。Markdown 预览使用轻量的自实现小函数（覆盖标题、列表、表格、粗体、双链转文本这几种常见语法即可，无需完整 CommonMark 支持）。

### 4.2 文件结构

```
dashboard/
├── index.html      # 页面骨架：顶部工具栏 + 视图容器 + 详情侧滑面板
├── style.css        # 样式
├── app.js           # 数据加载、渲染、排序、筛选、预览、跳转逻辑
└── data.json         # 由脚本生成，不手工编辑
```

### 4.3 页面布局

- 顶部工具栏：
  - 视图切换按钮（表格 / 卡片）
  - 银行类型多选筛选（国有大行/股份行/城商行/农商行）
  - 命题状态多选筛选（开放/加强/削弱/证实/证伪/未知）
  - 数据生成时间展示（读取 `generated_at`）
- 表格视图（默认）：
  - 列分组表头：基础信息｜盈利能力（ROE/NIM/营收增速/净利增速）｜资产质量（不良率/拨备覆盖率/拨贷比）｜资本规模（CET1/总资产）｜估值（PB/PE/股息率）｜研究状态（命题状态标签/更新日期）
  - 点击列表头切换升序/降序排序（数值列按数字排序，`null` 排最后）
  - 缺失值显示为浅灰色 "NA"
  - 命题状态用颜色徽章展示（开放=蓝、加强=绿、削弱=黄、证伪/失效=红、证实=靛蓝、未知=灰）
- 卡片视图：
  - 每张卡片：银行名 + 类型标签 + ROE/NIM/不良率/拨备覆盖率四个核心指标 + 命题状态色标
  - 点击卡片展开显示其余指标（估值、资本、更新日期）
- 详情预览侧滑面板：
  - 点击表格/卡片中的银行名触发
  - 面板内渲染"核心命题"文件的开头摘要（命题定义章节）
  - 提供两个按钮：`在 Obsidian 中打开`（拼接 `obsidian://open?vault=银行&file=<url编码后的相对路径去掉.md>`）、`关闭`
  - Vault 名称在 `app.js` 顶部作为可配置常量 `OBSIDIAN_VAULT_NAME = "银行"`

### 4.4 加载方式说明

页面加载时用 `fetch('./data.json')` 获取数据。由于部分浏览器对 `file://` 协议下的 `fetch` 有跨域限制，`index.html` 内会提示：如遇加载失败，请在 `dashboard/` 目录下运行 `python3 -m http.server 8000` 后访问 `http://localhost:8000`。

## 5. 容错与边界情况

- 某银行三个来源文件中有文件缺失 → 该银行仍出现在列表中，缺失字段显示 NA，链接按钮置灰或不显示；
- 指标数值格式不规范（如包含多个数字、单位不一致）→ 提取失败时记为 `null`，不强行解析出错误数字；
- `data.json` 不存在或加载失败 → 页面显示明确的错误提示和刷新数据的命令提示，而非空白页。

## 6. 验证方式

- 运行 `python3 scripts/generate_dashboard_data.py` 后检查生成的 `dashboard/data.json` 是否包含18条记录，且抽查2-3家银行（如杭州银行、招商银行）的字段是否与源 Markdown 一致；
- 本地起 `http://localhost:8000` 打开页面，检查表格排序、筛选、视图切换、详情预览、Obsidian 跳转链接格式是否正确。
