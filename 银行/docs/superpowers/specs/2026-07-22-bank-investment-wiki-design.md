# 中国 A 股银行投资研究知识库设计

> 日期：2026-07-22  
> Vault：`/Users/yangjintai/Documents/LLM wiki/银行`  
> 定位：面向 3–5 年中长期基本面投资的中国 A 股上市银行研究系统  
> 状态：设计已确认，待用户审阅后进入实施计划

## 1. 目标与边界

### 1.1 研究目标

建立一个可持续维护、可验证、可审计的 Obsidian LLM Wiki，用于中国 A 股上市银行的中长期投资研究。估值是知识库的一部分，但不是知识库的唯一目标。

知识库需要支持：

- 系统理解银行业商业模式、监管约束和宏观传导机制；
- 对全部 A 股上市银行进行基础覆盖；
- 对 18 家重点银行进行深度基本面研究；
- 严格区分官方事实、第三方数据、市场预期、研究推断和估值假设；
- 将静态结论转化为可持续验证的投资命题；
- 在季报、年报和重大事件后增量更新，而非反复重建；
- 支持同业比较、A/H 对照、风险证伪、估值和 3–5 年股东回报拆解。

### 1.2 市场与投资周期

- 核心市场：中国 A 股上市银行；
- A/H 两地上市银行：共用基本面研究页，分别维护价格、估值、股息与市场预期；
- 投资周期：3–5 年中长期基本面投资；
- 季度信息的角色：验证长期投资命题，而非服务短线择时；
- 数据截点：以 2026-07-22 前已正式披露的最新数据为准，原则上以 2025 年年报为完整基准，以 2026 年最新正式季报更新边际变化。

### 1.3 不在首版范围内

- 高频交易、技术分析和日内资金流；
- 自动交易或仓位管理系统；
- 未经正式披露的经营数据；
- 以单一券商目标价替代独立估值；
- 为每家银行创建独立 Vault；
- 首版建设复杂数据库或 Web 应用。

## 2. 方案选择

采用“行业 Wiki + 投资驾驶舱”混合架构。

### 2.1 被否决的方案

1. 严格通用行业 Wiki：行业认知完整，但投资命题、预期差、估值和复盘不突出。
2. 一股一库投资驾驶舱：适合单家公司，但会复制宏观、监管和概念页面，不利于 18 家银行横向比较。

### 2.2 选择混合架构的原因

- 复用 `industry-llm-wiki` 的原始资料层、知识库层和导航层；
- 复用行业库的证据等级、双链、来源索引和维护契约；
- 吸收 `茅台PRO` 的投资命题、反方论证、市场预期、估值和判断变更机制；
- 宏观、监管和核心概念只维护一份；
- 所有上市银行基础覆盖，18 家重点银行深度覆盖；
- 适合长期增量维护和跨银行比较。

## 3. 总体架构

知识系统分为六层：

1. 原始资料层：监管资料、定期报告、公司公告、AkShare 快照、市场预期资料；
2. 行业认知层：商业模式、宏观监管、资产负债表、盈利、风险和资本；
3. 公司研究层：全量基础档案和 18 家重点银行深度研究；
4. 投资命题层：行业及个股命题、正反证据、验证阈值和证伪条件；
5. 估值与决策层：PB-ROE、RIM、DDM、情景分析、预期回报和判断变更；
6. 跟踪维护层：月度/季度/年度跟踪、来源管理、健康检查和操作日志。

知识流如下：

```text
官方披露 / AkShare / 市场预期
              ↓
         原始资料只读存档
              ↓
       口径清洗与证据分级
              ↓
     行业页面 / 银行公司页面
              ↓
       投资命题与反方论证
              ↓
    跟踪指标 → 验证 → 证伪
              ↓
       估值、决策与判断复盘
```

## 6. 银行业研究框架

研究传导链：

```text
宏观与监管
→ 资产负债结构
→ 净息差与非息收入
→ 资产质量与信用成本
→ 资本生成与分红
→ 正常化 ROE
→ 估值与股东回报
```

### 6.1 宏观、货币、财政与监管

覆盖 GDP、通胀、社融、信贷、M2、LPR、政策利率、存款挂牌利率、收益率曲线、财政扩张、地方化债、房地产和银行监管。研究重点是政策对规模、息差、信用成本和资本消耗的传导，而非政策新闻汇编。

### 6.2 商业模式与银行分类

按国有大行、股份行、城商行和农商行分组，并增加零售型、对公型、财富管理型、金融市场型、区域深耕型和县域下沉型标签。跨行比较必须先选择合理同业组。

### 6.3 资产负债表

拆解贷款、债券投资、票据、同业资产；对公、零售、按揭、经营贷、消费贷和信用卡；存款、同业负债、同业存单和金融债；活期/定期、零售/对公存款结构。识别规模增长是有效需求还是低收益冲量。

### 6.4 盈利能力

跟踪净利息收入、净息差、净利差、生息资产收益率、计息负债成本率、手续费、中收、投资收益、公允价值变动、成本收入比、PPOP、ROA 和 ROE。

```text
NIM 变化
= 资产收益率变化
- 负债成本率变化
+ 资产负债结构贡献
```

### 6.5 资产质量

除不良率外，跟踪关注类、逾期、逾期 90 天以上、新生成不良、核销、转让、清收，及房地产、地方平台、小微、信用卡、消费贷、区域和行业集中度风险。

### 6.6 拨备与利润质量

识别利润来自收入改善还是少提拨备，判断信用成本是否低于正常水平，检查拨备覆盖率、拨贷比、不良生成、核销和拨备计提是否匹配，并观察 PPOP 与净利润背离。

### 6.7 资本、成长与分红

```text
可持续增长率 ≈ ROE × 留存率
```

跟踪核心一级资本充足率、一级资本充足率、资本充足率、RWA、资本补充工具、分红率和股息率。高增长、高分红和高资本安全垫之间存在约束。

### 6.8 护城河、治理与区域禀赋

护城河主要来自低成本稳定存款、区域客户关系、零售和财富管理、风险定价、不良处置、资本实力、逆周期扩张和公司治理。

## 7. 投资命题系统

### 7.1 双层命题

- 行业命题：如存款重定价能否推动净息差企稳、地方化债是否降低城商行尾部风险、高股息能否持续；
- 个股命题：如招商银行零售护城河、兴业银行金融市场能力、江苏银行增长质量、常熟银行下沉模式复制性。

### 7.2 命题字段

每条命题必须包含：

- 核心主张；
- 状态：开放、加强、削弱、证实、证伪、失效；
- 支持证据；
- 反对证据；
- 市场当前预期；
- 验证指标；
- 阈值与时间窗口；
- 证伪条件；
- 盈利影响；
- 估值影响；
- 关联和依赖命题。

每季度追加证据并更新状态，不删除旧判断。判断变化进入只追加日志。

## 8. 估值体系

### 8.1 PB-ROE

稳定期近似：

```text
P/B = (ROE - g) / (COE - g)
```

用于同业比较、历史分位、解释估值溢价和反推隐含长期 ROE。采用正常化 ROE，不直接外推单期 ROE。

### 8.2 RIM

```text
V0 = BV0
   + Σ[(ROE_t - COE) × BV_(t-1) / (1 + COE)^t]
   + 终值
```

RIM 是主内在价值模型，将银行价值拆为当前净资产和未来超额收益。建模前必须评估账面资产是否充分确认潜在损失。

### 8.3 DDM 与股息率

```text
P0 = D1 / (COE - g)
```

用于分红稳定、资本安全垫较高的成熟银行，并与国债、信用债、A/H 股息率和自身历史分位比较。

### 8.4 PE

仅用于阶段性盈利预期和历史区间交叉检查。拨备、信用成本及投资收益可能显著扭曲单期 PE。

### 8.5 三情景和回报拆解

每家重点银行设置悲观、基准和乐观情景，包含资产增速、NIM、非息增速、信用成本、正常化 ROE、分红率、COE 和终值增长率。

```text
3–5 年总回报
≈ 盈利与净资产增长
+ 股息回报
+ 估值变化
- 资本补充摊薄
```

## 9. 事实、预期和判断隔离

页面信息分为六类：

1. 官方事实；
2. 第三方结构化数据；
3. 外部预期；
4. 研究推断；
5. 估值假设；
6. 未知或待验证。

外部预期必须注明来源、数据日期、预测期间、样本机构数量（若可得）、与实际披露的差异及可能滞后。

## 10. AkShare 数据管线

### 10.1 定位与证据等级

AkShare 用于批量取数和交叉检查，不替代官方披露。AkShare 原始数据默认 `medium`，与年报、公告或监管资料复核的数据点可提升为 `high`。

优先级：

```text
监管与政府官方数据
> 上市银行正式披露
> AkShare 等第三方结构化数据
> 市场预期
> 研究推断
```

### 10.2 数据覆盖

- 行情与市值：`stock_zh_a_hist`、`stock_hk_hist`、实时行情与个股信息；
- 标准财务：`stock_yjbb_em`、三大报表、财务分析指标和财务摘要；
- 估值：`stock_value_em`、历史估值和同行比较；
- 分红与股东：历史分红、巨潮分红、港股派息、十大流通股东。

银行现金流量表不使用一般企业自由现金流解释。

### 10.3 快照组织

```text
02_原始资料/04_AkShare数据/
├── 行情与市值/
├── 财务摘要/
├── 财务报表/
├── 历史估值/
├── 分红/
├── A-H对照/
└── 数据字典与运行记录/
```

规则：

- 原始快照不手工修改；
- 原始字段和清洗结果分离；
- 记录 AkShare 版本、接口、参数、执行时间和异常；
- 同一批次使用统一估值基准日；
- CSV 存放结构化快照，Markdown 存放研究结论；
- 接口失败时不静默沿用旧数据，标记最后成功日期。

## 11. 数据口径

### 11.1 时间口径

- 2025 年年报是完整基准；
- 2026 年最新已正式披露季报用于边际更新；
- 行情和估值注明具体交易日期；
- 累计季报不误作单季度；
- 同比使用相同报告期间。

### 11.2 指标词典

每个指标记录中文名、英文缩写、公式、分子分母、监管含义、披露差异、可比性限制和官方出处。至少覆盖 NIM、净利差、ROA、ROE、不良率、关注率、逾期率、新生成不良率、信用成本、拨备覆盖率、拨贷比、资本充足率、LCR、NSFR、PPOP、成本收入比、RWA 和风险密度。

### 11.3 A/H 口径

- A 股人民币，H 股港元；
- 价格和市值比较记录汇率；
- 区分税前和实际税后股息率；
- A/H 溢价注明公式和日期；
- 基本面共享，交易价格和投资者回报分开。

## 12. 更新机制

### 12.1 月度

LPR、政策利率、社融、信贷、M2、国债收益率、重要信用利差、地产数据、股价、PB、PE、股息率和 A/H 溢价。

### 12.2 季度

重点银行核心指标、全量基础比较、NIM、非息、成本收入比、资产质量、拨备、信用成本、资本、RWA、预期差和命题状态。

### 12.3 半年度和年度

全面更新深度页、正常化 ROE、RIM、DDM、三情景估值、治理、区域、客群、业务结构、分红持续性、风险地图和反方论证。

### 12.4 事件驱动

降准降息、存款利率调整、地产和化债政策、监管规则、管理层变更、资本补充、重大风险、处罚及分红政策变化。

## 13. 错误处理

### 13.1 数据冲突

保留双方原始值，检查报告期、合并范围、币种、单位和调整口径，以正式披露为准，在验证日志记录冲突和解释，不覆盖历史。

### 13.2 接口失败

记录接口、参数、时间和错误，尝试已知替代接口，不用未经核验的搜索摘要补值，页面显示最后成功日期，关键缺失会降低页面成熟度或证据等级。

### 13.3 异常数据

检查会计政策、合并范围、一次性因素、核销、转让、重组和拨备释放；不将异常增长机械外推；加入验证日志和下一期跟踪清单。

## 14. 模板要求

首版至少创建：

1. 银行基础档案模板；
2. 重点银行深度研究模板；
3. 投资命题模板；
4. 财报更新模板；
5. 季度复盘模板；
6. 通用知识页面模板；
7. 来源笔记模板。

模板必须约束 Frontmatter、证据类型、来源、数据日期、相关页面、待验证和下一步。

## 15. 跟踪器

至少创建：

1. 宏观与政策跟踪器；
2. 息差与收入跟踪器；
3. 资产质量跟踪器；
4. 资本与分红跟踪器；
5. 催化剂日历；
6. 全量银行核心指标比较表；
7. A/H 估值对照表。

每个指标应关联投资命题、更新频率、来源、阈值和当前状态。

## 16. 验收标准

### 16.1 结构

- 目录、维护契约、导航、索引和日志完整；
- 至少七类模板；
- 全部 A 股上市银行有基础档案；
- 18 家重点银行有深度研究页；
- 双链均指向真实页面；
- 知识页 Frontmatter 完整。

### 16.2 内容

- 研究框架覆盖宏观、负债、息差、非息、资产质量、拨备、资本、治理和估值；
- 每家重点银行至少一个投资命题和一个反方观点；
- 事实、第三方数据、预期、推断和假设分层；
- 关键结论有来源或标为待验证；
- 银行特有指标有定义和口径。

### 16.3 数据

- AkShare 快照可追溯至接口、参数、版本和日期；
- 18 家重点银行具有统一核心指标表；
- 关键指标经正式披露抽样复核；
- A/H 数据处理币种、汇率和股息税；
- 估值注明价格日和报告期；
- 不使用尚未正式披露的数据冒充事实。

### 16.4 投资研究能力

知识库能够回答：

- 银行靠什么赚钱；
- ROE、风险和资本的主要驱动是什么；
- 利润增长是真实经营改善还是拨备影响；
- 核心命题、反方证据和证伪条件是什么；
- 悲观、基准和乐观情景分别是什么；
- 未来 3–5 年股东回报如何拆解；
- 如何在季度财报后增量更新命题。

## 17. 实施原则

- 先搭结构、维护契约和模板，再批量摄入数据；
- 先建立行业框架和指标词典，再写公司判断；
- 先用 AkShare 建立批量底表，再用官方披露复核关键指标；
- 重点银行按统一模板研究，但允许突出商业模式差异；
- 全局导航、索引、来源和日志在每个实施阶段同步更新；
- 首版结束时执行结构、链接、Frontmatter、来源和数据口径健康检查；
- 不自动提交 Git，除非用户明确要求。
