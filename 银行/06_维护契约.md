# 06 维护契约

本契约约束整个 Vault 的页面结构、信息分层、证据规则、更新方式和日志纪律。它的目标不是限制写作，而是保证这个银行研究库能够长期增量维护、可追溯、可复核、可审计。

相关页面：[[06A_银行业数据口径规范]]、[[03_模板/银行基础档案模板]]、[[03_模板/重点银行深度研究模板]]、[[03_模板/投资命题模板]]、[[03_模板/财报更新模板]]、[[03_模板/季度复盘模板]]、[[03_模板/通用知识页面模板]]、[[03_模板/来源笔记模板]]。

## 1. 适用范围

本契约适用于以下全部内容：

- `02_原始资料/` 下的原始来源与快照说明页；
- `05_知识库/` 下的行业页、公司页、命题页、估值页、风险页、跟踪页；
- 根目录治理文件与后续的 `[[07_导航首页]]`、`[[08_索引]]`、`[[09_操作日志]]`；
- 所有由模板新建的研究笔记、来源笔记、更新笔记与复盘笔记。

不适用范围：

- 自动生成的 CSV、JSON 等结构化快照文件本体；
- 临时抓取失败日志的原始命令输出；
- 与本 Vault 无关的外部文件。

## 2. 不可破坏的全局原则

### 2.1 研究边界

- 研究对象是中国 A 股上市银行；
- A/H 同一主体共享一套基本面研究页面，不为 H 股另建重复公司基本面页；
- A/H 的价格、估值、股息率、汇率、税务和市场预期必须分开记录；
- 投资周期为 3-5 年，季度更新用于验证长期命题，不用于短线交易叙事。

### 2.2 原始资料只读

- `02_原始资料/` 存放原始材料、来源摘录和 AkShare 快照说明；
- 原始快照不做手工篡改；
- 如发现源数据错误，只能新增纠错说明，不覆盖原始留档；
- 研究结论写在 `05_知识库/`，不要写回原始快照页冒充事实层。

### 2.3 先证据、后判断

- 任何定量结论都必须能追溯到来源页或正式披露；
- 无法确认的内容进入“未知或待验证”，不能直接升级为研究结论；
- 外部预期与估值假设可以存在，但必须和事实层隔离；
- 不使用尚未正式披露的数据冒充已确认事实。

## 3. YAML Frontmatter 最低要求

除纯目录说明页外，所有 Markdown 页面都必须带 YAML frontmatter。最小公共字段如下：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 页面标题，建议与文件名一致 |
| `note_type` | 是 | 页面类型，例如 `bank_profile`、`deep_research`、`investment_thesis` |
| `status` | 是 | `draft`、`active`、`reviewed`、`archived` 之一 |
| `created` | 是 | 首次创建日期，格式 `YYYY-MM-DD` |
| `updated` | 是 | 最近一次实质更新日期，格式 `YYYY-MM-DD` |
| `data_cutoff` | 是 | 页面内容使用的数据截点 |
| `report_period` | 建议 | 如 `2025A`、`2026Q1` |
| `evidence_level` | 是 | 页面当前主证据等级 |
| `evidence_class` | 是 | 页面当前主信息类别，枚举见 3.1 |
| `source_priority` | 是 | 当前主来源优先级，枚举见 3.1 |
| `sources` | 是 | 关联的来源页双链列表 |
| `related` | 建议 | 关联页面双链列表 |
| `tags` | 是 | 便于筛选与聚合 |

推荐统一使用如下骨架：

```yaml
---
title: <页面标题>
note_type: <页面类型>
status: draft
created: <YYYY-MM-DD>
updated: <YYYY-MM-DD>
data_cutoff: <YYYY-MM-DD>
report_period: <2025A/2026Q1/NA>
evidence_level: <high/medium/low/mixed>
evidence_class: "official_fact"
source_priority: "company_filing"
sources:
  - "[[来源页1]]"
related:
  - "[[相关页1]]"
tags:
  - 银行
---
```

### 3.1 可执行枚举与 `mixed` 例外

- `evidence_level` 仅允许：`high`、`medium`、`low`、`mixed`；
- `evidence_class` 仅允许：`official_fact`、`third_party_data`、`external_expectation`、`research_inference`、`valuation_assumption`、`unknown_pending`、`internal_governance`、`mixed`；
- `source_priority` 仅允许：`regulator`、`company_filing`、`third_party_structured`、`market_expectation`、`research_inference`、`internal_governance`、`mixed`；
- `evidence_class: internal_governance` 与 `source_priority: internal_governance` 只用于本库原创的契约、口径和模板说明，不表示监管或公司官方背书；
- `mixed` 只允许用于模板页（`note_type` 以 `template_` 开头）、导航/索引/看板，以及确实按章节隔离多类信息的复合研究页：`deep_research`、`earnings_update`、`quarterly_review`、`knowledge_page`；
- `bank_profile`、`investment_thesis`、`source_note` 等具有明确主责任的页面不得将 `source_priority` 设为 `mixed`；它们应填写当前主来源优先级；
- 校验器应拒绝枚举外的值，并按上述 `note_type` 白名单检查 `mixed`。模板文件顶部 frontmatter 允许 `mixed`，模板内“建议 frontmatter”仍应选择目标页面可执行的安全值。

补充规则：

- `updated` 只在实质内容更新时修改，纯格式调整可不改。

## 4. 页面类型与职责

| `note_type` | 用途 | 典型位置 |
| --- | --- | --- |
| `source_note` | 记录单一来源、摘录、元数据与提取事实 | `05_知识库/10_来源/` 或原始资料说明页 |
| `bank_profile` | 全量银行基础档案 | `05_知识库/03_银行库/` |
| `deep_research` | 重点银行深度研究 | `05_知识库/03_银行库/` |
| `investment_thesis` | 行业或个股投资命题 | `05_知识库/17_投资命题/` |
| `earnings_update` | 财报更新与边际变化记录 | `05_知识库/20_决策与复盘/` |
| `quarterly_review` | 季度复盘与命题验证 | `05_知识库/20_决策与复盘/` |
| `knowledge_page` | 通用知识、监管、框架、概念 | `05_知识库/` 各子目录 |
| `governance_contract` | 全库规则和维护约束 | 根目录 |
| `data_policy` | 数据口径、指标词典、A/H 规则 | 根目录 |

一页只承担一个主责任。不要把“来源摘录、行业知识、个股判断、估值模型、复盘日志”混写进同一页。

## 5. 六类信息隔离规则

所有研究页必须显式区分以下六类信息：

1. 官方事实 `official_fact`
2. 第三方结构化数据 `third_party_data`
3. 外部预期 `external_expectation`
4. 研究推断 `research_inference`
5. 估值假设 `valuation_assumption`
6. 未知或待验证 `unknown_pending`

### 5.1 隔离要求

- 同一段落只表达一种主信息类别；
- 同一张表如混合多类信息，必须新增 `信息类别` 列逐行标识；
- “市场一致预期”不得写入“官方事实”；
- “我认为/我们判断”不得写入“第三方结构化数据”；
- “估值模型参数”不得写成“公司已披露事实”；
- “待验证事项”不得伪装成结论性措辞。

### 5.2 推荐章节顺序

对大多数研究页，推荐按以下顺序组织：

1. 范围与结论摘要
2. 官方事实
3. 第三方结构化数据
4. 外部预期
5. 研究推断
6. 估值假设
7. 未知或待验证
8. 来源与关联页面
9. 只追加更新日志

这不是唯一目录结构，但六类信息必须能被读者一眼区分。

## 6. 证据等级与来源优先级

### 6.1 证据等级

| 等级 | 含义 | 允许使用场景 |
| --- | --- | --- |
| `high` | 由监管、政府官方或银行正式披露直接支持，或已与正式披露逐项复核 | 核心事实、关键指标、正式结论 |
| `medium` | 有可信来源支持，但尚未完成官方逐项复核 | AkShare 快照、结构化第三方数据、交叉检查结果 |
| `low` | 仅作线索或辅助，不足以支撑结论 | 零散媒体摘要、二手转述、未经复核的推测 |
| `mixed` | 聚合页或导航页含多种等级信息 | 导航、索引、综述页 |

### 6.2 来源优先级

统一采用以下优先级：

```text
监管与政府官方数据
> 上市银行正式披露
> AkShare 等第三方结构化数据
> 市场预期
> 研究推断
```

执行规则：

- 冲突时先比来源优先级，再比报告期、口径、币种、单位与披露时间；
- 同优先级冲突时，保留双方并记录差异，不做静默覆盖；
- `AkShare` 原始数据默认 `medium`；仅在与年报、公告或监管资料逐项复核后，相关数据点才能升级为 `high`；
- 任何 `high` 结论都必须能追到正式来源页。

## 7. Obsidian 双链规范

目录只用代码格式表示，例如 `05_知识库/10_来源/`；双链只指向 Markdown 页面，不指向文件夹。来源笔记统一位于 `05_知识库/10_来源/`，写作格式为 `[[05_知识库/10_来源/<页面名>]]`。

### 7.1 必须使用双链的场景

- 来源页与被引用研究页之间；
- 行业页与公司页之间；
- 公司页与投资命题页、估值页、风险页之间；
- 财报更新页与对应银行深度页、命题页之间；
- 通用知识页与术语页、监管页、跟踪器之间。

### 7.2 链接书写规则

- 优先使用 `[[页面名]]` 或 `[[路径/页面名]]`；
- 同一概念只有一个主页面，避免同义重复建页；
- 需要兼容别名时，使用 `aliases` 维护，而不是复制内容；
- 引用来源时，优先链接到来源笔记页，而不是裸 URL；
- 页面首次出现核心概念时，补上相关双链。

### 7.3 禁止事项

- 把一个事实在多个页面各写一份长期分叉维护；
- 用纯文本提到关键概念却不建立双链；
- 用未命名、无 frontmatter 的散页充当正式节点。

## 8. 来源管理规则

### 8.1 定量信息

`draft` 或快速采集页允许渐进补链：尚未建好来源页时，可在“待验证事项”记录来源题名、URL/文件路径和补链动作，`sources` 可暂为空列表 `[]`，但不得创建错误路径或伪链接。页面升级到 `active` 或 `reviewed` 前，必须完成有效来源双链。

所有关键定量信息在 `active` / `reviewed` 状态至少要满足以下四项：

- 来源页双链；
- 数据日期；
- 报告期；
- 单位或币种。

### 8.2 外部预期

外部预期必须明确写出：

- 来源机构或来源集合；
- 数据日期；
- 对应预测期间；
- 样本机构数量（若可得）；
- 与正式披露相比的可能滞后或偏差。

### 8.3 研究推断

`draft` 状态允许先记录推断和待补来源；升级到 `active` / `reviewed` 时，研究推断必须显式写出其依赖的事实与假设，至少链接：

- 一个事实来源页；
- 一个相关知识页或命题页；
- 一个待验证的后续跟踪项。

## 9. 数据冲突处理规则

出现数据冲突时，按以下顺序处理：

1. 保留双方原始值，不删除任何一方；
2. 检查报告期是否一致；
3. 检查合并范围是否变化；
4. 检查币种、汇率、单位是否一致；
5. 检查是否为调整后口径、年化口径、单季口径或累计口径；
6. 以正式披露为当前主口径；
7. 在验证日志或操作日志中记录冲突、解释、处理结论和待跟踪事项。

推荐记录格式：

```markdown
- 2026-07-22 | 指标: <指标名> | 冲突双方: <来源A> vs <来源B> | 检查项: 报告期/币种/单位/口径 | 当前采用: <来源> | 原因: <说明> | 后续动作: <待验证事项>
```

禁止做法：

- 直接用后来的值覆盖之前的值且不留痕；
- 未区分单季与累计季报就写同比或环比结论；
- 涉及 A/H 比较或投资者实际回报时，未核对币种、汇率日期和适用税务假设就写结论。

## 10. A/H 口径维护规则

- 同一银行的基本面分析只维护一页；
- A 股与 H 股的交易信息分栏记录；
- A 股价格与市值使用人民币，H 股使用港元；
- 做 A/H 对照时必须记录汇率日期；
- 税前股息率始终记录；仅当页面用于 A/H 比较、跨市场实际回报或明确投资者身份时，才必须计算税后股息率并披露税务假设；否则税后字段填 `NA` 并说明“不适用/尚未设定投资者身份”；
- A/H 溢价必须注明公式和日期；
- 若只拿到单边市场数据，明确写 `NA`，不要假定另一边同步。

## 11. 更新频率与只追加日志

### 11.1 更新频率

- 月度：宏观利率、社融、估值分位、A/H 溢价等；
- 季度：重点银行核心财务与命题状态；
- 半年/年度：深度研究、估值模型、治理与商业模式重估；
- 事件驱动：监管政策、资本补充、分红政策、重大风险事件、管理层变化。

### 11.2 只追加日志规则

以下内容必须采用只追加方式维护：

- 投资判断变化；
- 命题状态变化；
- 财报解读结论变化；
- 数据冲突与纠偏记录；
- 估值参数重大调整；
- 研究错误与事后复盘。

只追加的含义：

- 新增条目写在日志顶部或底部，但不删除旧条目；
- 旧判断即使失效也保留，并显式标注“已失效/已证伪/被替代”；
- 可以更新页面顶部“当前结论摘要”，但必须同步新增一条日志说明为何变化；
- 只有拼写、排版、死链修复这类不改变含义的修改，才允许直接原地改写且不记实质日志。

推荐日志区块：

```markdown
## 只追加更新日志
- 2026-07-22 | 类型: 创建 | 变更: 建立页面骨架 | 依据: [[来源页]] | 影响: 当前无结论变化
- 2026-08-30 | 类型: 判断调整 | 变更: 将命题状态由“开放”改为“加强” | 依据: [[财报更新页]] | 影响: 提高后续验证优先级
```

## 12. 页面成熟度与发布纪律

### 12.1 状态定义

- `draft`：结构已建或处于快速采集阶段，允许来源页和相关页渐进补链，但必须把缺口列入“待验证事项”；
- `active`：已可用于研究工作，核心来源齐备；
- `reviewed`：关键数据经过正式披露复核；
- `archived`：仅保留历史，不再主动维护。

### 12.2 从草稿到可用的最低门槛

页面要从 `draft` 升为 `active`，至少满足；`reviewed` 还需完成关键数据的正式披露复核：

- frontmatter 完整；
- 页面主结论有来源；
- 六类信息未混写；
- 关键数字带日期和报告期；
- 相关双链可追到上游来源或下游命题页。

## 13. 执行检查清单

每次新建或大改页面后，至少自检以下项目：

- 是否有 frontmatter；
- `note_type` 是否正确；
- 是否明确了 `data_cutoff` 与 `report_period`；
- 是否区分六类信息；
- 是否给关键数字标明来源、日期、单位和币种；
- 若为 `draft`，缺失双链是否已记录为待验证动作；若为 `active` / `reviewed`，所有必需来源与关联双链是否真实可达；
- 是否补了“未知或待验证”；
- 是否需要新增只追加日志条目；
- 若涉及 A/H，对照口径是否齐全；只有涉及跨市场实际回报或投资者身份时才强制核对税后股息率及税务假设；
- 若使用 AkShare，是否仍保持默认 `medium` 或写清升级依据。

## 14. 本契约与模板的关系

模板不是可选建议，而是本契约的落地载体：

- 新建公司页，优先从 `[[03_模板/银行基础档案模板]]` 或 `[[03_模板/重点银行深度研究模板]]` 开始；
- 新建命题页，使用 `[[03_模板/投资命题模板]]`；
- 新建财报跟踪与季度复盘页，分别使用 `[[03_模板/财报更新模板]]`、`[[03_模板/季度复盘模板]]`；
- 新建行业与概念页，使用 `[[03_模板/通用知识页面模板]]`；
