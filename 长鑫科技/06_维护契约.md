> 本文件定义 LLM agent 维护本知识库时必须遵守的规则。研究对象为长鑫科技股份有限公司/长鑫存储（CXMT），重点为 DRAM 存储芯片与晶圆制造。

## 1. 架构

```
原始资料层 (02_原始资料/)  →  知识库层 (05_知识库/)  →  导航层 (07_公司主页 + 08_索引 + 13_跟踪器)
       ↑                          ↑                          ↑
```

## 3. 证据等级

证据等级严格使用以下五档映射之一，不得自定义：

- `监管`（high）：证监会、交易所、央行、统计局等监管或官方机构原始披露。
- `官方`（high）：公司官网、官方公告、招股书、年报、季报、官方公众号、官方转载稿。
- `行业机构`（medium）：TrendForce、Counterpoint、Omdia、Gartner、IC Insights、SEMI、SEAJ 等可独立访问的行业机构数据。
- `新闻媒体`（low）：媒体、券商研报、第三方分析、KM 内部转载片段、社交媒体。
- `待验证`（low）：来源不可访问、仅有单一来源、未交叉核实或市场估算。

关键规则：

1. 未经证实的判断必须标记为 `待验证`，不得在页面正文中作为事实陈述。
2. 永远不要自动把单一来源（特别是 KM 片段）升级为确定结论。
3. 数据必须标注来源编号（如 `S01`）或链接，并在所属资料节点页注明能/不能支持的论断。
4. 涉及 CXMT 主体身份、证券代码、上市状态、上市日期、营收、利润、产能、资本开支、客户结构、市值或目标价等字段，未取得监管/官方文件前一律填写 `待确认` / `待补充` / `待验证`。
5. 自身之前的推断默认是 `low`，只有被同类来源或更新数据交叉验证后才升级。
6. 任何不可访问或仅得到片段的内容不可标 `high` 证据。

## 4. 页面内容结构

每个页面优先使用以下短节：

- **一句话判断**：这个页面在说什么，核心结论是什么；在证据不足时显式标注 `待验证`。
- **事实**：已确认的数据和信息（标注来源编号和报告期）。
- **推断**：基于事实的合理推论（标注证据等级与推断理由）。
- **关联页面**：`[[双链]]` 指向相关页面。
- **待验证**：需要验证的问题清单。
- **下一步**：具体的验证行动。

`[[双链]]` 引用只使用文件名（不含路径）。

## 5. 操作工作流

### 5.0 强制日志规则

每次创建、修改或删除 Wiki 页面后，必须在同一任务中更新 `09_操作日志.md`，不得把日志更新留到下一次任务。新日志插入文件顶部说明文字之后，按时间倒序排列；同一天有多条记录时，最新发生的记录排在前面。日志至少记录：

- `Changed`：修改了哪些页面及核心变化
- `Why`：修改原因
- `Data Source`：使用的数据与资料来源；无新增来源时写"无"
- `Next`：后续待办；无待办时写"无"

完成任务前必须检查本次 Wiki 文件变更均已被当次日志覆盖。`09_操作日志.md` 的历史记录内容不得改写；允许为维持倒序而移动完整日志块，新记录只在顶部插入。

### 5.1 财报/公告发布后更新

1. 更新 `03_财务分析/` 相关页面（只 touch 需要更新的页面）
2. 更新 `08_估值假设/`（参数是否需要调整）
3. 更新 `13_跟踪器/` 季度指标
4. 在 `12_验证日志/` 标记哪些假设被验证/证伪
5. 在 `09_操作日志.md` 顶部插入新记录
6. 检查 `11_决策记录/` 里是否有需要复盘的项

### 5.2 重大行业事件后更新

1. 在 `10_事件时间线/` 新增事件页面（如设备出口管制更新、节点路线图公布、客户认证公告、价格剧烈波动等）
2. 更新 `09_风险地图/`
3. 更新 `04_护城河/` 动态评估
4. 评估是否触发 `11_决策记录/` 的新决策
5. 在 `09_操作日志.md` 顶部插入新记录

### 5.3 健康检查（半年一次）

1. 检查估值假设是否过时
2. 检查风险地图是否完整（周期、出管制、技术、产能、良率、客户认证、CapEx、融资）
3. 检查决策记录是否有未复盘项
4. 检查是否有孤立页面（无 `[[双链]]` 的页面）
5. 检查来源索引是否覆盖最新公告与行业资料
6. 如健康检查导致任何 Wiki 内容变化，在 `09_操作日志.md` 顶部插入新记录

### 5.4 半导体专用更新场景

针对 DRAM 行业研究的高频更新场景，统一流程如下：

- **DRAM 行业价格/供需变化**：先在 `02_原始资料/新闻事件/` 登记来源（Sxx），再更新 `07_先行指标/DRAM先行指标` 与 `13_跟踪器/长鑫跟踪器` 的当期快照。
- **工艺节点/产能扩张公告**：在 `02_原始资料/公告/` 登记来源，更新 `03_财务分析/资本开支与产能` 与 `04_护城河/长鑫护城河`。
- **客户认证/重大订单**：在 `02_原始资料/新闻事件/` 登记，更新 `02_业务地图/长鑫业务地图` 与 `09_风险地图/长鑫风险地图`（客户集中度）。
- **设备/材料出口管制更新**：在 `02_原始资料/公告/` 登记美国 BIS、荷兰 ASML、日本 METI 等原始公告，更新 `09_风险地图/长鑫风险地图`（出口管制）与 `06_竞争格局/DRAM竞争格局`。
- **CapEx 公告/融资事项**：在 `02_原始资料/公告/` 登记，更新 `03_财务分析/资本开支与产能`、`03_财务分析/现金流质量` 与 `08_估值假设/长鑫估值假设`。

## 6. 半导体专用写作规范

- 使用中文，技术术语保留英文（如 DDR5、LPDDR5、HBM、wafer starts、CapEx、bit shipment）。
- 避免绝对化语言（参见用户写作风格偏好）。
- 数据必须标注来源编号（`Sxx`）+ 报告期；无来源的字段标注 `待验证` / `待补充` / `待确认`。
- 严格区分事实、推断、假设；任何 CXMT 自身数字未取得官方证据前均进入 `待验证`。
- 大量使用 `[[双链]]` 构建知识网络。
- 页面应短而精，不写长报告。
- Obsidian `[[双链]]` 只引用文件名（不含路径）。
- 财务数据来源统一标注：`Sxx，<报告期 YYYY-Qx 或 YYYY年报>`。
- 行业数据来源统一标注：`Sxx，<机构>，<报告期/出版日期>`。
- 未取得公司官方材料的内部指标（产能、资本开支、良率、客户结构）一律 `待补充`；纳入财务、估值、跟踪页面时显式标注 `待验证` 状态。

### 6.1 半导体指标口径要点

| 指标 | 口径要点 | 注意事项 |
|------|----------|----------|
| 产能（wafer starts / 月） | 折合 12 英寸等效晶圆月产能 | 区分建成 vs 实际投产；区分洁净间 vs 工艺设备 |
| 良率（yield） | 单一片合格品/晶圆投片数 | 区分 wafer 良率、die 良率、最终测试良率 |
| 制程节点 | 公司披露的工艺代号（如 1x/1y/1z/1α/1β、17nm） | 节点命名 ≠ 实际物理尺寸，需以官方定义为准 |
| Bit 产出 | 晶圆投片 × die 数 × 良率 | 与产能、良率强相关，周期低点/高点差异显著 |
| 资本开支 CapEx | 设备 + 厂房 + 其他长期资产 | 区分维持性 vs 增量；区分货币口径（人民币/美元） |
| 折旧 | 晶圆厂与设备折旧周期 | 八年制程摩尔定律使折旧周期与产能爬坡错配 |
| DDR / LPDDR / HBM | 按代次与用途分类 | DDR 与 LPDDR 单价、毛利差异较大 |
| 客户认证 | 模组厂、OEM、服务器/手机厂商 | 区分送样、测试、量产三个阶段 |
| 周期 | DRAM 合约价 / 现货价 | 区分现货价 vs 合约价；区分 OEM vs 渠道 |

## 7. 反编造与红/橙线

- 严禁编造 CXMT 的证券代码、上市状态、上市日期、营收、利润、毛利率、产能、资本开支、研发费用、客户结构、市场份额、市值或目标价。
- 严禁在 `02_原始资料/` 之外直接填写具体数字；先在 `02_原始资料/` 完成取证后再回填。
- 严禁把"KM 搜索片段""自媒体推算""券商预测"写成公司事实；只能作为 `待验证` 线索或外部观点。
- 严禁用其他公司（如 SK 海力士、美光）的数字反推 CXMT 的指标。
- 严禁在同一页内无引用地写出"业内估计""约 XX""通常认为"等模糊措辞；必须明确证据等级。
- 严禁以"长鑫科技"统称所有合肥长鑫系实体；必须区分主体与关联实体。
- 红线：所有写入正文的数字必须可追溯到 `Sxx` 编号；无来源 → `待验证`。
- 橙线：所有写入正文的主体性事实（如证券代码、上市状态）必须经过监管/官方二级核验；缺一不可。
